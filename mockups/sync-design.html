A version is the same concept wherever it's born — externally as a file (the llm's draft) or internally when a session diverges (your air while the mini saved). Files are how versions cross the boundary; inside, they're writer-labeled sources. .llm.md already works this way today.

Writer ids, shortest that stays readable: llm mini air ph pad avp. Two windows on one device share an id — a same-writer collision becomes air2, rare enough to never see.

2Where this sits — seven ideologies of conflict

Exclude

locks before edit — RCS, SVN lock, Word check-out

Reject

stale write refused — ETag/412, Wikipedia

Merge

3-way vs base — diff3, git, Unison

Transform

reorder ops live — OT, Google Docs

Converge

merge by construction — CRDT, Yjs, Automerge

Commute

patches as algebra — Darcs, Pijul

Embrace

fork on conflict, human merges — Dropbox copies, CouchDB siblings, Bayou, git branches

xccms = Embrace, borrowing Merge's one lesson: remember the base. The store knows what every session loaded, so "only the divergent parts" is a 3-way diff, not a guess. Embrace's known failure is orphaned conflict copies that rot unread — because Dropbox and CouchDB had no merge UI. A CMS does: the reference pane already pulls chunks from a version. The historically missing piece is the part that's already built.

3One save, three outcomes

base = current doc (the 99% case)→update the doc · simple.md re-rendered · done
base moved, but text identical→no-op — already converged
base moved, text differs→text kept as the air version · source pane appears

Never happens: overwrite (the lost-update bug), blocked save (locks), silent machine merge. Offline is the same path — an offline device reconnects, saves against its old base, and its text becomes its version. Offline support costs nothing extra.

4Reconcile — only the divergent parts

Simple… where?

Simplicity is a claim people make about the part of the system they happen to be looking at. The complexity didn't vanish — it moved.

air changed thisThe question worth asking isn't "is this simple?" but "where did the complexity go?" Someone is holding it. If it's not you, find out who.

Frameworks advertise the part they simplified. The invoice for the part they didn't arrives later, itemized as configuration.

Same pane as the llm draft today, pointed at any writer's version — but showing only divergent blocks, and 3-way aware: the store remembers each session's base, so "you changed it / they changed it / both did" is computable and untouched blocks never appear. Blocks are computed at diff time (existing splitBlocks + neighbour-content anchoring) — no ids stored anywhere, no identity problem.

7Boundary rules — when files are touched

eventfiledirection
llm (or anything external) writes a draftx.llm.mdin — becomes a version
importing existing markdownx.mdin — becomes a new post
every savex.mdout — re-rendered, so git history, backups, and the llm always see current content
publishx.mdout — the pipeline reads the rendered file, unchanged from today
someone edits x.md directly on diskx.mdin — detected by hash, imported as an ext version instead of being clobbered

Assumption to veto: x.md keeps being re-rendered on every save (not only at publish). It costs nothing and keeps git as a dense backup and the file readable by anything — but the file is a rendering, no longer the truth while a post is being edited.
