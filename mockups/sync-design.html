Versions & conflict — design

One writer per version file · .md in, .md out · conflict is a file, not an error

1The model — a post is a main file plus writer versions

notes/simple.mdthe post — the only file publish ever reads
notes/simple.llm.mdllm  llm's version — already exists today
notes/simple.air.mdair  macbook air's version — born from a conflicting save
notes/simple.ph.mdph  iphone's version — only exists while it diverges

.llm.md was never a special case — it's the first instance of the general rule: a writer that doesn't currently own main writes its own version file. Everything stays plain markdown, git-tracked. Publish, deploy hashes, git history: all unchanged, all reading main only.

Writer ids, shortest that stays readable: llm mini air ph pad avp. Two windows on one device share an id — a same-writer collision forks to air2, which should be rare enough to never see.

2Where this sits — seven ideologies of conflict

Exclude

locks before edit — RCS, SVN lock, Word check-out

Reject

stale write refused — ETag/412, Wikipedia

Merge

3-way vs base — diff3, git, Unison

Transform

reorder ops live — OT, Google Docs

Converge

merge by construction — CRDT, Yjs, Automerge

Commute

patches as algebra — Darcs, Pijul

Embrace

fork on conflict, human merges — Dropbox copies, CouchDB siblings, Bayou, git branches

xccms = Embrace, borrowing Merge's one lesson: remember the base (every save already commits, so the base is always a git commit — 3-way diffs are free). Embrace's known failure is orphaned conflict copies that rot unread — because Dropbox and CouchDB had no merge UI. A CMS does: the reference pane already inserts chunks from a sibling version. That missing piece is the part that's already built.

3One save, three outcomes

base = current main (the 99% case)→write simple.md · commit · done
base moved, but text identical to main→no-op — already converged
base moved, text differs→write simple.air.md · commit · reconcile chip appears

Never happens: overwrite (the lost-update bug), blocked save (locks), silent machine merge. Offline is the same path — an offline device reconnects, saves against its old base, and forks. Offline support costs nothing extra.

4Reconcile — only the divergent parts

Simple… where?

Simplicity is a claim people make about the part of the system they happen to be looking at. The complexity didn't vanish — it moved.

air changed thisThe question worth asking isn't "is this simple?" but "where did the complexity go?" Someone is holding it. If it's not you, find out who.

Frameworks advertise the part they simplified. The invoice for the part they didn't arrives later, itemized as configuration.

Same pane as the llm draft today, pointed at any writer version — but showing only divergent blocks, and 3-way aware: base in git means "you changed it / they changed it / both did" is computable, so untouched blocks never appear. Blocks are computed at diff time (existing splitBlocks + neighbour-content anchoring) — no ids stored in the markdown, no identity problem.

7Open question — when is a version file born?

Lazy recommended

simple.md ← everyone, optimistically simple.air.md ← born only on conflict

Zero friction when there's no conflict — which for one person is almost always. The llm stays eager (it never owns main). Sibling files exist only while something actually diverges.

Eager

simple.mini.md ← mini, always simple.air.md ← air, always simple.md ← assembled via reconcile

Every edit needs a merge step to reach main — friction on the 99% case to simplify the 1%. Conflicts impossible, but main is never directly yours.
